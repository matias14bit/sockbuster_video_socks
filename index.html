ARQUITECTURA DE SOFTWARE PARADIGMA 4+1

Especificación arquitectónica de Sockbuster Video & Socks bajo el modelo de Philippe Kruchten, articulando los Requerimientos Funcionales (RF01-RF04) y No Funcionales (RNF01-RNF02) mediante diagramas UML estandarizados y código declarativo PlantUML.

1. Lógica 2. Desarrollo 3. Procesos 4. Física 5. Escenarios
CRITERIO 2.1.1 • MATRIZ DE TRAZABILIDAD

VINCULACIÓN DE REQUERIMIENTOS CON VISTAS 4+1

4 RF + 2 RNF Cubiertos
Código Requerimiento del Negocio Vistas 4+1 Impactadas Artefactos / Implementación Web
RF01 Catálogo por Colecciones Temáticas: Exploración y filtrado por categoría, foto, precio, stock y tallas. Lógica, Desarrollo, Escenarios Clases Coleccion y Producto; módulo Gestor de Catálogo y Filtros.
RF02 Carrito y Gestión de Pedidos: Agregar ítems, modificar cantidades, validar stock y simular checkout con ID único. Lógica, Procesos, Escenarios Clases ItemCarrito y Pedido; secuencia síncrona de checkout (SB-2026-XXXX).
RF03 Administración de Inventario: Registrar modelos, asociar película/serie, actualizar stock y modificar precios. Lógica, Desarrollo, Escenarios Subclase Administrador (gestionarInventario(), actualizarStock()) y endpoints API REST.
RF04 Gestión de Reseñas de Fanáticos: Valoraciones de 1 a 5 estrellas y comentarios en la ficha de cada producto. Lógica, Escenarios Clase Resena vinculada a Cliente y Producto; modal interactivo de reseñas.
RNF01 Disponibilidad y Despliegue en la Nube: Carga inicial óptima (<2s) y hosting público accesible vía web. Desarrollo, Física Arquitectura estática desacoplada desplegada en GitHub Pages / Vercel / Netlify con assets SVG ligeros.
RNF02 Seguridad en Acceso y Autenticación: Comunicación cifrada HTTPS y autenticación mediante tokens JWT. Desarrollo, Física, Escenarios Middleware Autenticación JWT, Controlador JWT Auth y transporte TLS/HTTPS extremo a extremo.
